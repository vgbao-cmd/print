# Live Avatar Printer

A Windows desktop app that turns TikTok LIVE likes and gifts into animated, full-color avatar prints. This is an on-screen printer. No physical printer, driver, TikFinity, or paid speech service is required.

## Run on Windows

Double-click **Start-Live-Avatar-Printer.cmd**. If an unpacked release is present, the launcher opens `release/win-unpacked/Live Avatar Printer.exe`. Keep the entire `win-unpacked` folder together. A portable EXE is also generated by `npm run dist` when the packaging tools are available.

Two windows open: **Control Panel** and **Broadcast Output**. Closing Control Panel exits the app. Closing Broadcast Output leaves Control Panel open; use **Open Broadcast Window** to bring it back. Printing waits until Broadcast Output is ready.

For a source checkout, use Node.js 22 LTS or the included `.tools/node-v22.23.4-win-x64` runtime:

```powershell
$env:PATH = "$PWD\.tools\node-v22.23.4-win-x64;$env:PATH"
npm ci
npm run build
npm start
```

Other commands: `npm run dev`, `npm test`, `npm run benchmark`, `npm run smoke`, `npm run check:visual`, `npm run check:premium`, `npm run check:shows`, `npm run pack`, `npm run dist`.

## Try Demo Mode

1. Open **Demo lab** while disconnected from TikTok.
2. Press **250 LIKES**. Jamie receives exactly two classic prints and keeps 50 likes toward the next one. Remaining likes on the desk is the sum across viewers; it is never used to award another viewer's print.
3. Try **100 LIKES**, **MANY VIEWERS**, and each print style.
   **PHOTO AVATAR** uses a bundled NASA sample portrait to test real photographic colors without a TikTok connection. It is not a TikTok viewer or a real gift.
   All individual tier buttons now use that same color portrait. **COMPARE CLASSIC / ROYAL / HALL OF FAME** adds those three rewards; **ALL STYLES · SAME PHOTO** adds all eight tiers. The real print scheduler remains active during Demo.
4. **COMBO ×5** sends intermediate and repeated final updates. Only one combined print is created, with quantity ×5. Demo gifts have synthetic IDs and use the suggested coin values only for preview counters; no real gift or money is sent.
5. **DUPLICATE EVENT** creates one entitlement. **UNICODE & BAD AVATAR** tests names and fallback images. The generated demo includes international viewer names; names are not translated.
6. **1,000 EVENTS** runs a synthetic burst. **CROSS SPEED THRESHOLDS** adds 90 classic prints.
7. Pause printing, close the app, and reopen it to check recovery. STOP keeps the exact current print and spotlight checkpoint when reopening. Use RESUME to continue. Without STOP, a crash may restart an unfinished animation.

Demo print styles are independent of the real gift guide. Demo shows the labeled suggestion preview; LIVE hides unverified entries and warns in Control Panel. Demo does not connect to TikTok or start a livestream.

## Connect to TikTok LIVE

1. The account must already be LIVE. Enter its `@username` in Control Panel and select **Connect**. This app never starts a livestream.
2. Wait for **CONNECTED**. A failed/offline connection is reported in English. Reconnection uses bounded backoff and retains stored receipts.
3. Settings → **REFRESH GIFT LIST** fetches the actual gift list for this room. The app also tries this after connecting. The connector's signing provider may be unavailable or rate limited; no paid account or API key is enabled automatically.
4. Select **VERIFY SUGGESTED GIFTS** to match unique exact names and prices, or choose a real catalog gift manually. Missing suggestions remain unverified. Legendary requires Takoyaki at 88 COINS. The dropdown and verified broadcast guide show the actual configured price.
5. Give a gift a manual English display name if the source does not provide an English name. Gift IDs, image URLs and prices are taken from the connector catalog, not invented.
6. Select **SAVE SETTINGS**. A gift ID can only map to one tier. Unmapped gifts still contribute known coin values to Top Supporters but do not create prints.

Likes use each identified viewer's received `count`/`likeCount` delta. With the default rule, 250 likes gives two classic prints and a 50-like remainder. Room totals are ignored. **Counts reflect only data received by this app**, which may differ from TikTok's displayed totals. Events without reliable user/event IDs are skipped to avoid duplicate rewards on reconnection. Native combo gifts require a group ID and final update; incomplete or unidentifiable combos are not guessed.

The installed connector is **tiktok-live-connector 2.5.0**, with its native v3 protobuf payload. Avatar URLs are read from `user.avatarThumb.urlList`, then medium/large variants, with a legacy `profilePictureUrl` fallback. User IDs support native `id`/`idStr`. Gift prices use `gift.diamondCount`; combo identity uses `groupId`. Initial historical data processing is disabled.

## Capture in TikTok LIVE Studio

1. Open **Broadcast Output**.
2. In LIVE Studio, add a **Window Capture** source and select **Live Avatar Printer — Broadcast Output**. Use window content capture and crop any operating-system title bar/border if your capture mode includes them.
3. Use a **1080 × 1920** portrait canvas and fit the source to it. The scene is always laid out at 1080 × 1920 and scales if you resize the output window. It requests a 1080 × 1920 content area; Windows may constrain its visible size to the monitor.
4. Add application audio capture for the output process/window as supported by your LIVE Studio version. Select the Electron/Live Avatar Printer audio session and test both sound and voice. Avoid capturing the same audio twice through desktop audio.
5. Preview the layout in Studio before going LIVE. The right side and bottom contain less important content; TikTok overlay positions vary by device, region and Studio layout. Adjust the source crop/position as needed.

Only the animated scene appears in Broadcast Output. Configuration, diagnostics and internal paths stay in Control Panel or local logs. Keep the output window open; closing it returns uncompleted prints to the durable queue.

## Settings, sound and queues

The broadcast uses a large, front-facing roll-paper printer. A moving guide and print head scan the new circular avatar at the top of the sheet, print the viewer name, then feed the continuous sheet. Earlier prints retain their individual sizes. The lower sheet bends gently. There is no separate Recent Prints area or 3D display table.

## Premium sizes, spotlights and music

The default CLASSIC avatar diameter is 128 source pixels. The following are diameter multipliers; HALL OF FAME therefore has sixteen times the circular area of CLASSIC.

| Tier | Avatar Scale | Default spotlight | Built-in audio |
| --- | ---: | ---: | --- |
| CLASSIC | ×1 | Off | Printer motor and ticks |
| GLOW | ×1.25 | Off | Short sparkle |
| BLOOM | ×1.5 | 2 seconds | Gentle bell motif |
| LOVE | ×2 | 3 seconds | Playful melody |
| ROYAL | ×2.5 | 5 seconds | Coronation motif |
| RAINBOW | ×3 | 7 seconds | Bright electronic arpeggio |
| LEGENDARY | ×3.5 | 9 seconds | Low epic motif |
| HALL OF FAME | ×4 | 12 seconds | Victory motif |

Suggested targets are 1 / 5 / 10 / 20 / 30 / 88 / 100 COINS; live mappings require the current room catalog. CLASSIC remains the default per-viewer like reward. Actual replacement gift prices are always used; the app never converts coins to currency.

Settings → **Print styles & spotlights** lets you change Avatar Scale (0.5–4), Spotlight Duration (0–30 seconds), Spotlight Enabled, Music File, Music Volume and Voice Enabled for every tier. Defaults above are restored with Restore Defaults, then Save Settings. A zero duration does not create a spotlight even if its switch is on. Changes apply to new entitlements; existing queued rewards keep their saved size, duration and tier audio settings.

Paper spacing is calculated from each avatar diameter, frame padding, name area and row gap. Larger rewards can show fewer historical entries at once. A preparation feed makes room before a larger next print, and the final feed is capped so the new large print still fits vertically. Grouped printing respects those same dimensions. Names wrap at word boundaries when possible and preserve Unicode grapheme clusters.

After a qualifying print completes, its spotlight is added atomically to a separate SQLite queue. Only one spotlight is displayed at a time. The original print stays on the sheet, printing continues behind the spotlight, and no print timer waits for music, voice or the effect. BLOOM has flowers, LOVE hearts, ROYAL a crown/gold frame, RAINBOW animated colors, LEGENDARY an orbiting light dragon and HALL OF FAME a commemorative frame/confetti. Entry and exit are included in the configured spotlight duration. Combo ×N is displayed once; quantity does not multiply spotlight duration.

The Control Panel shows **SPOTLIGHT QUEUE** independently of Print Queue. Large backlogs remain in SQLite; they are not silently skipped or held as an unbounded array in RAM. If gifts arrive faster than spotlight playback, their waiting time will increase. RESET SESSION can clear active and waiting work after explicit confirmation. Clear Queue only clears the explicitly confirmed waiting print jobs; it does not discard already-earned spotlights.

**Music Volume**, **Print Sounds Volume** and **Voice Volume** are separate global controls. Each tier also has its own music multiplier and Voice Enabled switch; the global English voice switch remains the master. Music fades at its boundaries, only one music track runs at a time, and the music bus ducks while TTS speaks. Printer sounds can continue underneath music. Default themes are synthesized locally from original procedural motifs.

**CHOOSE MUSIC** accepts a local MP3, WAV, OGG, M4A or FLAC file up to 20 MB and copies it to the application's `music` directory. Save Settings to apply it. The source file can then be moved without breaking the saved copy. Unsupported or unreadable audio falls back to a built-in theme and reports an English message in Control Panel. Long tracks are stopped with a fade at the spotlight boundary. For tiers without a spotlight, an optional custom cue is short and never interrupts an active spotlight track. **USE BUILT-IN THEME** removes the assignment; it does not delete files referenced by older queued rewards.

The print head and reveal mask use the same scan coordinates. An unvisited part of the avatar is transparent until the head reaches its strip. Name printing has its own pass after the avatar. Scan density falls from 32 to 24 to 16 lines as printing speeds up; grouped printing uses eight lines per avatar and feeds three distinct rows within the configured batch duration. Preparation, name printing, parking and paper feeding are all included in that duration.

- Default speed: 0–10 waiting prints → 3 seconds; 11–30 → 2 seconds; 31–80 → 1 second; above 80 → groups of 3 in 1.5 seconds. Adjust thresholds and all four durations in Settings. Speed changes at batch boundaries; a 20% low-water margin prevents oscillation.
- Every grouped print keeps its own avatar/name. After at most three gift prints, a waiting like print is served. Each category is FIFO.
- A completed gift combo creates one decorated print showing its quantity; it credits the actual unit coin value × final quantity once.
- Pause Printing stops the next batch. The current batch finishes. Clear Queue asks for confirmation and reports the waiting count; the active print finishes.
- Save Settings before testing sound or voice. Sound is synthesized locally with a motor, roller ticks and tier-specific chimes. English TTS uses installed system/browser voices only. If none are available, Settings shows **No English voice available**. The printer still works. Viewer names are preserved; pronunciation varies by voice.
- Voice requests run sequentially, use a maximum of four waiting messages, and aggregate thanks during busy periods. TTS never blocks event intake or printing.
- Use **RESET SESSION** to clear the current session after confirmation, even while connected or busy. Receipt and combo protection persist across sessions. Reconnecting to the same room does not reset its balances. Different rooms have separate balances/supporter lists; queued entitlements are preserved until served or explicitly cleared.

## Storage and resource limits

Data is stored under `%APPDATA%/Live Avatar Printer/` in `printer.sqlite` with a WAL journal. Settings, per-viewer balances, combo receipts and pending work commit locally. Back up this directory while the app is closed. Do not delete it to resolve a connection problem.

The queue stays in SQLite; only the current batch and eight preview rows are sent to the UI. Multi-like entitlements are stored as counted rows and split only when served. Image requests have four concurrent downloads, a six-second timeout, a 2 MB transfer limit, a bounded wait list, aspect-preserving resizing to a 512-pixel long edge and a 128-entry/16 MB/six-hour memory cache. Only HTTPS TikTok/ByteDance CDN images are fetched; avatar failures use a colored fallback; gift images use the supplied real-image fallback or text only. Gift and avatar image requests never block event intake.

The sheet shows as many entries as the actual tier sizes allow. At most twelve lightweight completed metadata records are retained; only visible entries plus one buffer entry, the active batch and the single active spotlight have textures. Off-screen textures are released. Avatar downloads preserve aspect ratio and are reduced to at most 512 pixels on the long edge. Two reusable 1080 × 1920 canvases draw the background and source, and one bounded 800 × 1100 canvas draws the curved sheet. A spotlight has at most forty decorative particles, and the audio scheduler only prepares a short window of notes. Broadcast drawing is capped at 30 frames/second; the control preview is capped at 15. The last twelve paper entries and the single honored guest persist. Closing the output saves a stopped checkpoint; reopen it and choose RESUME.

Logs contain only stage/error class and no raw connector payloads, credentials or token-bearing URLs. SQLite receipts remain on disk to prevent replay of old events; disk use grows with session history. RAM does not hold that history. If storage fails or intake exceeds its explicit 2,048-event waiting bound, the app disconnects and reports the issue rather than silently discarding acknowledged entitlements. Check free disk space before a long session.

Completion is recorded after Broadcast Output acknowledges the animation. A print already committed as completed is not replayed. Print completion and spotlight creation share one SQLite transaction. An unfinished spotlight is restored after reopening; completed spotlight rows are removed. A crash between showing a print/effect and committing its acknowledgment can replay that *uncommitted* animation on restart; exact-once visual presentation across a power failure cannot be guaranteed. Incoming events that have not reached a SQLite commit can also be lost on abrupt power failure. Graceful exit drains received events.

## Validation and limitations

See **VALIDATION.md** and `artifacts/` for automated test, synthetic benchmark and Electron smoke-check results. Synthetic tests do not establish TikTok LIVE compatibility or sustained-load capacity. Real LIVE payloads, real gift images/prices, network signing, English voice playback and LIVE Studio audio capture must be checked in the target environment before production use.

The source is a separate project. It uses the same TypeScript, Electron, React, Vite and connector versions as the upstream 0.16.0 project, selectively adapting its connector lifecycle and SQLite/WAL ledger approach. No scene assets, Vietnamese speech models or unrelated functionality are included. See LICENSE and THIRD_PARTY_NOTICES.md.


## Premium performances and session controls (1.4.0)

Use **ROYAL / RAINBOW / LEGENDARY / HALL OF FAME** in Demo lab to queue all four shows with the same photographic avatar. Individual tier buttons remain available. Real gifts continue to use the configured room catalog IDs and actual coin prices; demo rewards never configure a real gift.

| Tier | Paper diameter | Default show | Performance |
| --- | --- | --- | --- |
| ROYAL | 2.5 times CLASSIC | 5 seconds | Opening gold frame, descending crown, ROYAL GUEST stamp |
| RAINBOW | 3 times CLASSIC | 7 seconds | Portal, avatar flight and moving color ribbons |
| LEGENDARY | 3.5 times CLASSIC | 9 seconds | Dimmed scene, coiling light dragon, supporter badge on the original print |
| HALL OF FAME | 4 times CLASSIC | 12 seconds | Gold machine, honor stage, largest avatar and confetti; returns to one HONORED GUEST slot |

Every show has its own original synthesized motif with an introduction, stronger middle section and closing phrase. Existing per-tier music files and volumes still work. Enable English thank-you voice in Settings for the spoken welcome. The Hall of Fame line is ?Welcome to the Hall of Fame, [Name]!? Only one large show and one music track play at a time. The print queue continues independently. Combo quantity does not multiply the show duration.

**STOP / RESUME** appears only in Control Panel, above the desk. STOP immediately freezes print and spotlight time, stops music and printer sounds, and cancels native speech. It does not disconnect TikTok. Received events keep committing to the durable queue. RESUME continues the same job tokens and remaining duration; interrupted speech restarts its short sentence. Built-in music resumes at the current musical section; a selected local track seeks to the elapsed position. Closing Broadcast Output also stops playback; reopen it and choose RESUME.

**RESET SESSION** asks for confirmation in English. It clears active and waiting prints, spotlights, speech, likes and remainders, paper history, rankings and the honored guest, then returns to READY TO PRINT. Gift settings, audio settings, account and TikTok connection remain. Event receipt and combo replay keys remain protected. Events already received before the reset boundary are recorded before clearing the old session; arrivals after that boundary belong to the new session.

The last twelve paper entries and the single honored guest are durable. Visible textures and effect resources remain bounded. Queued rewards wait on disk rather than being silently discarded.

The enlarged front-facing printer uses 960 source pixels of width. Paper is 800 pixels wide; avatars keep their circular geometry and original aspect ratio. The guide sits below the paper in four plus three cells. There are no placeholder gift icons or NOT CONFIGURED labels on the broadcast.

Suggested defaults, not confirmed LIVE prices or IDs:

| Finger Heart | 5 COINS | Bloom Print |

| Doughnut | 30 COINS | Rainbow Print |
| Takoyaki | 88 COINS | Legendary Print |
| Hand Heart | 100 COINS | Hall of Fame Print |

The preset list intentionally contains no gift IDs. On connection, the connector fetches the current room's gift catalog. The app matches a unique exact normalized English name and exact price, then stores the returned ID and metadata. It never chooses an unrelated same-price gift. Existing custom mappings are retained; the old Legendary default is migrated to the Takoyaki suggestion while its scale, dragon duration, music and voice settings remain. Legendary can only be verified as Takoyaki at 88 COINS. English display names can be edited in Settings.

A real print reward requires the configured ID, matching catalog name and price, a valid English display label, and verification for that same room. If an event includes a price, it must agree. Gifts awaiting a catalog, missing from it or mismatching a saved mapping are held in a durable deferred table, shown in Control Panel and retried on verification. They are not guessed or discarded to reduce RAM. Reset Session clears deferred work but retains its receipt/combo replay protection.

Live Gift Guide entries come from those same verified settings. Unverified/missing entries are hidden on the broadcast and warned about in Control Panel. Demo always previews the seven suggestions, labeled GIFT GUIDE - DEMO PREVIEW, independently of custom live mappings. PREVIEW ALL 7 SUGGESTED GIFTS exercises seven synthetic tier rewards with the suggested prices; it does not establish real LIVE verification.

Room-catalog images take priority. The user-supplied CDN URLs and bundled copies of those exact images are fallbacks for matching suggestions. No fake gift icon replaces a failed image; if all sources fail, its real name, price and style remain. Downloads are limited to four at once, 2 MB per file and a bounded wait queue. Positive image caches are limited to 128 entries / 16 MB in RAM and on disk, with a six-hour lifetime. Failed URLs have a one-minute retry delay. Static WebP gifts are supported directly; two decoder slots limit memory while larger avatars are resampled to at most 512 pixels. Extremely large or animated WebP inputs are rejected.

See [LIVE-STUDIO-SETUP.md](LIVE-STUDIO-SETUP.md) for portrait capture and side-space diagnosis. The app does not use TikFinity.
